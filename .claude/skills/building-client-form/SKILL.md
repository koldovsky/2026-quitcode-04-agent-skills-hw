# Форма команди: Server Action + useActionState

Кожна форма в проєктах агенції робиться однаково: так її перевіряє будь-хто з команди за хвилину, а
типові аварії (дія без перевірки прав, помилки, яких не чує скрінрідер, `console.log(formData)`,
користувач чекає на лист) не з'являються. Правила Vercel — за id зі скіла
`vercel-react-best-practices`, тут їх не переписуємо.

## Коли застосовувати

- Нова форма або переробка наявної, якщо вона щось надсилає на сервер (створює, змінює, видаляє).
- **Не** застосовувати: клієнтський пошук/фільтр без відправки, суто вигляд форми, протокол зовнішнього
  сервісу (вебхук, n8n) — форма його лише викликає.

## Як робимо

Файли: дія — `app/<розділ>/actions.ts` (`"use server"`), форма — Client Component
`components/<назва>-form.tsx`, розбір полів — чиста функція `lib/<назва>-form.ts` (як `parseLeadForm`
у `lib/lead-form.ts`).

1. **Дія — публічний POST-ендпоінт** (`server-auth-actions`). Перший рядок дії — перевірка сесії
   (`getCurrentUser()` з `lib/data.ts`), далі — права на **конкретний** запис (запис належить workspace
   користувача), далі — валідація. Ні `proxy.ts`, ні перевірка на сторінці цього не замінюють: дію
   можна викликати прямим POST. Публічна форма без входу (заявка на сайті) — сесії немає свідомо;
   напиши це коментарем над дією, решта кроків та сама.
2. **Валідація на сервері** — функція `parse…Form(formData)` → `{ ok: true, data } | { ok: false, errors }`:
   `trim`, ліміт довжини кожного поля, перелік дозволених значень для `select`, числа через
   `Number.isFinite` (`0`, від'ємне, `NaN`, дробове — явно). HTML-атрибути (`required`, `maxLength`,
   `type="email"`) — лише підказка браузеру, не перевірка.
3. **Стан — `useActionState`** (з `react`), сигнатура дії `(prevState, formData)`. Тип стану:
   ```ts
   type FormState =
     | { status: "idle" }
     | { status: "invalid"; errors: Partial<Record<Field, string>>; values: Partial<Record<Field, string>> }
     | { status: "ok"; id?: string }
     | { status: "error" }; // збій без подробиць: без стеку, SQL, URL
   ```
   Дія повертає **лише** такий `{ status, … }` — не рядок з бази, не весь об'єкт (`server-serialization`).
4. **Введене не зникає.** React 19 після `<form action>` скидає неконтрольовані поля. Тому при
   `invalid` повертай `values` (лише текст, який ввів користувач) і став
   `defaultValue={state.values?.<поле>}` на кожне поле; `checkbox` — `defaultChecked`.
5. **Доступні помилки полів**: кожне поле має `<label htmlFor>`; при помилці —
   `aria-invalid="true"` і `aria-describedby="<id>-error"`, текст помилки в елементі з цим `id`; над
   формою — підсумок `role="alert"` («Перевірте N поля»), щоб його почув скрінрідер. Кнопка —
   `disabled={pending}` з текстом «Надсилаємо…».
6. **Працює без JavaScript**: `<form action={formAction}>` без `onSubmit` і без `e.preventDefault()`;
   жодних полів, що існують лише в стейті клієнта. Id запису, до якого належить форма, — **приховане
   поле** (`<input type="hidden" name="leadId" value={lead.id} />`), яке дія читає з `formData` і
   **авторизує** (крок 1). Не `useActionState(action.bind(null, id))`: у Next.js 16.3.5 / React 19.2
   відправка такої форми без JS на динамічному маршруті зависає — дія виконується, відповідь не
   приходить (перевірено). Захисту `bind` однаково не дає: зв'язані аргументи теж приходять від клієнта.
7. **Журнали без персональних даних**: ні `console.log(formData)`, ні `console.log(data)`, ні email,
   телефону, імені, IP. Можна: подію, id запису, код результату, тривалість.
8. **Повільне — в `after()`** з `next/server` (`server-after-nonblocking`): листи, аудит
   (`logAudit`), сповіщення, виклики зовнішніх сервісів. Запис, без якого дія не має сенсу, робиться
   **до** відповіді; `after()` — лише те, що може запізнитись. Потрібні заголовки чи cookie в
   `after()` — у Server Action їх можна читати всередині колбека.
9. Після зміни даних — `revalidatePath` сторінки, де їх видно; `router.refresh()` поверх нього не потрібен.

## Чекліст

```
- [ ] 1. Перший рядок дії — сесія (або коментар «публічна форма, без сесії»); права на конкретний запис.
- [ ] 2. Валідація в дії; ліміти довжини; 0 / від'ємне / NaN / порожнє для чисел оброблено.
- [ ] 3. Дія повертає лише { status, … }; немає return рядка з бази.
- [ ] 4. Після помилки введене на місці (values + defaultValue).
- [ ] 5. label + aria-invalid + aria-describedby на кожному полі з помилкою; підсумок role="alert".
- [ ] 6. Форма надсилається з вимкненим JavaScript.
- [ ] 7. grep по змінах: немає console.* з formData, email, phone, name.
- [ ] 8. Листи, аудит, зовнішні виклики — в after(); критичний запис — до відповіді.
```

## Зупинись і спитай людину, якщо:

- для перевірки прав бракує даних (у записі немає поля власника чи workspace) — не вигадуй правило;
- задача вимагає віддати в браузер повний запис або персональні дані іншого користувача;
- потрібна нова залежність (схема-валідатор, бібліотека форм) — `AGENTS.md`: пакети лише після «так»;
- форма має викликати зовнішній сервіс, для якого в проєкті немає домовленостей — питай про контракт.

      іншого workspace — теж.

- [ ] Час відповіді форми (DevTools → Network, `POST`) не включає листів і зовнішніх викликів.
