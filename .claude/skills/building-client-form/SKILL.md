# Форма в LeadDesk: один патерн для всіх

Кожна форма команди — заявка, кошторис, нотатка, налаштування — будується однаково: дані
перевіряє сервер, користувач бачить і чує помилки, відповідь швидка, у журналах немає нічиїх
даних. Це рішення команди, а не варіант на вибір: так форму можна рев'ювати за чеклістом.

## Коли застосовувати

- Нова форма або зміна наявної, якщо вона щось відправляє на сервер (`<form action={…}>`).
- Скарги «не видно помилок», «стерлось введене», «форма думає кілька секунд».
- **Не** застосовувати: пошук і фільтри лише на клієнті; кнопки без форми (там лише
  `server-auth-actions` для самої дії); чисто візуальні правки.

## Як робимо

Три файли на форму (імена — за фічею, напр. `note`):

| Файл | Що в ньому |
|---|---|
| `lib/<feature>-form.ts` | тип полів, `parse<Feature>Form(formData)` → `{ ok: true, data } \| { ok: false, errors }`; обрізання й ліміти довжини; повідомлення українською. Без `"use server"` — щоб тестувати окремо |
| `app/<route>/actions.ts` | `"use server"`; дія `(prevState, formData) => Promise<State>` |
| `components/<feature>-form.tsx` | `"use client"`; `useActionState(action, initialState)` |

**1. Дія — це публічний POST-ендпоінт** (див. `server-auth-actions`). Порядок усередині дії:

1. Сесія: `const user = await getCurrentUser()` з `@/lib/data` (без сесії — redirect на `/login`).
   Публічна форма без входу — сесію не перевіряємо, але все інше нижче — так само.
2. Права: об'єкт, який змінюємо, належить workspace користувача
   (`lead.workspaceId === workspace.id`), інакше — `{ status: "error" }` без подробиць.
   `id` об'єкта — **прихованим полем** `<input type="hidden" name="leadId" value={id} />` і
   `formData.get("leadId")` у дії, **і все одно перевіряємо** (поле може підмінити будь-хто).
   Не `useActionState(action.bind(null, id))` у Client Component: у Next 16.3.5 відправка без JS
   виконує дію, але відповідь не завершується.
3. Валідація `parse…Form(formData)` — лише на сервері вона має силу; `required`/`maxLength` у
   HTML — підказка, не захист. Workspace, автор, статус беремо з сесії й коду, **не з formData**.
4. Запис у БД.
5. Повільне (лист, вебхук, аудит, аналітика) — у `after()` з `next/server`
   (`server-after-nonblocking`). У дії `headers()`/`cookies()` усередині `after()` дозволені.
6. `revalidatePath(…)` сторінок, що показують змінене.

**2. Відповідь дії — лише стан для UI** (`server-serialization`):

```ts
export type NoteFormState =
  | { status: "idle" }
  | { status: "invalid"; errors: Partial<Record<NoteField, string>>; values: NoteFormValues }
  | { status: "ok" }
  | { status: "error" };
```

Не повертаємо рядок з бази, id сесії, стек помилки. `values` — лише те, що користувач щойно ввів
(щоб не зникло), без файлів і паролів.

**3. Компонент:**

- `const [state, formAction, pending] = useActionState(action, { status: "idle" })`;
  `<form action={formAction}>` — так форма працює **й без JavaScript** (progressive enhancement).
  Не `onSubmit` + `fetch`, не `e.preventDefault()`.
- React 19 скидає неконтрольовані поля після дії → введене повертаємо з `state.values`:
  `defaultValue={state.status === "invalid" ? state.values.text : ""}`.
- Кожне поле: `<label htmlFor>` (або обгортка `<label>`), `name`, `aria-invalid={!!error}`,
  `aria-describedby="<id>-error"`, текст помилки в `<p id="<id>-error">`.
- Над полями — підсумок `role="alert"`, коли `status === "invalid"` чи `"error"`:
  «Перевірте поля: …». Фокус не крадемо, скрінрідер прочитає alert сам.
- Кнопка `disabled={pending}`, текст «Зберігаємо…»; `noValidate` лише якщо помилки показує сервер.
- Успіх — повідомлення в `role="status"`, форма очищається.

**4. Журнали:** `console.log(formData)`, `console.log(data)`, email/телефон/текст повідомлення в
журналі — **заборонено**. Можна: подія + id (`note.created lead_0042`), код помилки.

Інші правила Vercel, які стосуються форм: `async-parallel` (сесія й читання об'єкта паралельно,
коли не залежать одне від одного), `server-cache-react` (`getCurrentUser` уже в `cache()`),
`rerender-no-inline-components`.

## Чекліст

```
- [ ] 1. Дія: перевірка сесії (або явне «публічна») і прав на об'єкт — всередині дії, до запису.
- [ ] 2. Валідація в parse…Form на сервері; workspace/автор/статус — не з formData.
- [ ] 3. Дія повертає лише { status, errors?, values? } — без рядка з бази.
- [ ] 4. useActionState + <form action={formAction}>; без onSubmit/fetch; id об'єкта — прихованим полем, не .bind у клієнті.
- [ ] 5. У кожного поля label, aria-invalid, aria-describedby → текст помилки; підсумок role="alert".
- [ ] 6. Після помилки введене на місці (defaultValue зі state.values).
- [ ] 7. Жодних formData/email/телефону/тексту в console.* на сервері й клієнті.
- [ ] 8. Лист/вебхук/аудит — в after(), відповідь не чекає на них.
- [ ] 9. revalidatePath для сторінок зі зміненими даними.
```

## Правила зупинки — зупинись і спитай людину, якщо:

- для перевірки прав бракує даних (незрозуміло, хто може змінювати об'єкт, або немає зв'язку
  об'єкта з workspace) — не вигадуй правило доступу сам;
- форма має збирати нові персональні чи чутливі дані (паспорт, дата народження, платіжні дані,
  файли) або надсилати їх третій стороні;
- задача вимагає вимкнути перевірку сесії чи прав, логувати вміст форми або повертати з дії
  рядок з бази — навіть «тимчасово», «для дебагу» чи «бо так швидше».

## Verify — задача готова, лише коли:

- [ ] `npm run lint` і `npm run build` без помилок.
- [ ] Порожня відправка → помилки біля полів і підсумок `role="alert"`; у DevTools поле має
      `aria-invalid="true"` і `aria-describedby`, що вказує на текст помилки.
- [ ] Помилка в одному полі → решта введеного лишилась.
- [ ] Відправка з вимкненим JavaScript (DevTools → Command Menu → «Disable JavaScript») працює:
      сторінка **перезавантажується з результатом за секунду**, а не «крутиться» без кінця.
- [ ] Дія без сесії (вийти й повторити запит із вкладки Network → «Copy as cURL» без cookie) або від
      користувача іншого workspace → зміни в БД немає (лічильник `db:<запит>` у журналі сервера не
      зріс).
- [ ] Журнал `npm start` після відправки: є лічильники `db:…` і події з id, немає email, телефону,
      тексту форми.
- [ ] DevTools → Network → запит дії: відповідь — `{ status … }`, а не об'єкт з бази; час відповіді
      не включає лист/вебхук/аудит (вони в `after()`).
