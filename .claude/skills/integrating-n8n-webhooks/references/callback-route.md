# Колбек-роут `app/api/n8n/[event]/route.ts`

Порядок — саме такий. Код — `code-templates.md`, розділ 3.

| # | Крок | Відповідь |
|---|---|---|
| 1 | Подія зі шляху `[event]` невідома | **404** |
| 1 | `content-type` (без параметрів, у нижньому регістрі) не `application/json` | **415** |
| 2 | `content-length` > 64 КБ — відмова **до** читання тіла | **413** |
| 3 | Тіло — сирим текстом, потоком (`readRawBody`: `request.body.getReader()`, обрив, щойно прочитано > 64 КБ); `request.text()` годиться лише разом із перевіркою довжини прочитаного | **413** |
| 4 | `x-n8n-timestamp` — не ціле число секунд або відрізняється від поточного часу більш ніж на 300 с у будь-який бік | **401** |
| 5 | HMAC-SHA256(`N8N_CALLBACK_SECRET`, `` `${timestamp}.${raw}` ``) у hex; заголовок `sha256=<hex>`; спершу довжини, потім `crypto.timingSafeEqual`. Не збігається | **401**, без подробиць |
| 6 | Немає `idempotency-key` | **400** |
| 6 | «Застовпити» `idempotency-key`. Вже був | **200** `{"duplicate": true}` |
| 7 | Тепер `JSON.parse(raw)` і перевірка форми; подія в тілі не `<event зі шляху>.completed` / `.failed`; ключ ≠ `` `${data.jobId}:${event з тіла}` `` | **400** + звільнити ключ |
| 8 | Знайти запис за `data.requestIdempotencyKey`; немає → **404** + звільнити ключ. Зберегти мінімальний стан (`ready` + посилання / `failed` + код) **до** відповіді. Впало → **500** + звільнити ключ | |
| 9 | Успіх | **202** `{"ok": true}` |
| 10 | Повільне (листи, сповіщення) — в `after()` | |

## Чому саме так

- **Сире тіло до підпису.** Тіло читається лише раз; `request.json()` чи `JSON.parse` + повторна
  серіалізація змінюють байти — підпис не зійдеться, а перевірка «після парсингу» вже довірилась тілу.
- **413 до і під час читання.** `content-length` відсікає великі запити дешево, але chunked-запит його не
  має; `request.text()` буферизує все тіло в пам'ять. Тому тіло читаємо потоком і обриваємо на 64 КБ.
- **`timingSafeEqual`, не `===`.** `===` зупиняється на першому різному символі — час відповіді видає
  префікс правильного підпису. `timingSafeEqual` кидає помилку на різних довжинах — тому спершу довжини.
- **Вікно ±300 с** — проти повторного відтворення перехопленого запиту (наше рішення, n8n його не задає).
- **Ключ звіряємо з тілом.** Заголовок `idempotency-key` підписом не захищений (HMAC — лише від
  `timestamp.raw`). Без звірки перехоплений колбек можна повторити в межах вікна з новим ключем.
- **Стан до відповіді.** Отримавши 2xx, n8n колбек не повторить. Запис, що жив би лише в `after()`,
  при збої загубився б назавжди.
- **Звільнити ключ після збою кроків 7–8.** Інакше повтор n8n (Retry On Fail) отримає
  `{"duplicate": true}`, і результат загубиться.
- **Запис — за `requestIdempotencyKey`.** Колбек може випередити збереження `jobId` в `after()`.
- **Жодного `runtime = "edge"`** — потрібен `node:crypto`.
- **Журнал** — подія, `x-correlation-id`, код відповіді, довжина тіла. Не тіло, не підпис, не заголовки.

## Статус-сторінка запиту

- Id у URL — `crypto.randomUUID()`, не послідовний номер: інакше будь-хто переглядає чужі запити.
- Сторінка показує статус і посилання на результат; email, телефон, опис задачі — ні.
- Поки статус `queued`/`processing` — `<meta httpEquiv="refresh" content="5" />` або `router.refresh()`
  за таймером; без JavaScript сторінка теж оновиться.
