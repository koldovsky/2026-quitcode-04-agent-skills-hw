# Режим відповіді n8n і тестовий vs production URL

## Режими вузла Webhook

| Режим | Що отримує Next.js | Коли використовуємо |
|---|---|---|
| Immediately | 200 одразу після отримання запиту | Подія «до відома», результат не потрібен (`lead-created`, аналітика) |
| When Last Node Finishes | Вихід останнього вузла після завершення воркфлоу | Швидкий запит (секунди), результат потрібен одразу |
| Using Respond to Webhook | Те, що задає вузол Respond to Webhook | **Стандарт для довгих задач:** 202 `{"job_id": …}` одразу, результат — колбеком |
| Streaming | Потік відповіді | Не використовуємо |

**Правило:** усе, що може наблизитись до **100 секунд**, — лише асинхронно (202 + колбек). На n8n
Cloud запит без відповіді за 100с завершується кодом **524**; воркфлоу далі працює, але Next.js вже
не дізнається про результат. Не певні, скільки триває воркфлоу, — вважайте його асинхронним.

Respond to Webhook спрацьовує один раз; наступні такі вузли ігноруються.

## Тестовий і production URL

| | Тестовий URL | Production URL |
|---|---|---|
| Шлях | `/webhook-test/<path>` | `/webhook/<path>` |
| Коли працює | Після «Listen for test event», 120 секунд | Поки воркфлоу опубліковано |
| Дані видно в редакторі | Так | Ні |

У коді й `.env.example` — лише `/webhook`. Тестовий URL — тимчасово, лише у власному `.env.local`,
коли дивитесь дані в редакторі n8n. Після кожної зміни воркфлоу — Publish знову (production
викликає опубліковану версію, не останні правки).
