# Режими відповіді вебхука й URL — як вибрати

## Режим (Response mode вузла Webhook)

| Режим | Що отримує Next.js | Коли |
|---|---|---|
| Immediately | 200 одразу після отримання запиту | подія «до відома», результат не потрібен: `lead-created`, аналітика |
| When Last Node Finishes | вихід останнього вузла після завершення | швидка довідка (секунди), коли результат потрібен у відповіді |
| Using Respond to Webhook | те, що задає вузол Respond to Webhook | **стандарт для довгих задач:** 202 `{"job_id": …}` одразу, результат — колбеком |
| Streaming | потік | не використовуємо |

**Правило 100 секунд.** Усе, що може наблизитися до 100 с, — лише асинхронно (202 + колбек). На n8n
Cloud запит, на який вебхук не відповів за 100 с, завершується **524**; воркфлоу працює далі, а
Next.js про результат уже не дізнається. **Не певні, скільки триває воркфлоу, — він асинхронний.**
«Кошторис 40–90 с», «генерація PDF», «звіт» — асинхронні.

Respond to Webhook спрацьовує один раз (наступні ігноруються). Якщо воркфлоу завершився, не дійшовши до
нього, — 200 зі стандартним повідомленням; помилка до нього — 500.

## Що це означає для коду

| Режим | Server Action | Колбек-роут |
|---|---|---|
| Immediately | запис → `after(() => triggerWorkflow(event, data, { idempotencyKey }))` → `{ status: "ok" }` | не потрібен |
| Respond to Webhook 202 | запис зі `status: "queued"` + `idempotencyKey` + `correlationId` → `after(() => triggerWorkflow(…, { callbackPath: "/api/n8n/<event>" }))` → `{ status: "ok", id }`; сторінка `/…/[id]` показує статус із БД | `app/api/n8n/[event]/route.ts`, оновлює статус на `ready`/`failed` |
| When Last Node Finishes | лише якщо **гарантовано** секунди; інакше — 202 + колбек | не потрібен |

Статуси запису для асинхронних задач: `queued` (збережено, n8n ще не викликано) → `processing`
(n8n відповів 202) → `ready` / `failed` (прийшов колбек) або `failed` (n8n відповів 4xx / вичерпано
повтори). Сторінка статусу читає з БД; автооновлення — `router.refresh()` за таймером або кнопка
«Оновити», без опитування n8n напряму.

## Тестовий і production URL

| | Тестовий | Production |
|---|---|---|
| Шлях | `/webhook-test/<path>` | `/webhook/<path>` |
| Коли працює | 120 с після «Listen for test event» у редакторі | поки воркфлоу **опублікований** |
| Дані видно в редакторі | так | ні |

- У коді й `.env.example` — **лише** `/webhook`. Тестовий URL — тільки у власний `.env.local`, поки
  дивитесь дані в редакторі n8n.
- n8n 2.x: публікація фіксує версію воркфлоу; production-виклики йдуть у неї, а не в останні правки.
  Після змін — Publish знову.
- На self-hosted шляхи змінюються змінними `N8N_ENDPOINT_WEBHOOK` / `N8N_ENDPOINT_WEBHOOK_TEST`. Якщо
  клієнт це зробив — записати в `docs/n8n-integrations.md` проєкту.
