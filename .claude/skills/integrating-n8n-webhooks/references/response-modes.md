# Режими відповіді вебхука й URL

## Який режим обрати

| Режим вузла Webhook | Що отримує Next.js | Коли |
|---|---|---|
| Immediately | 200 одразу після отримання | подія «до відома», результат не потрібен: `lead-created`, аналітика |
| When Last Node Finishes | вихід останнього вузла після завершення | швидка довідка (секунди), коли результат потрібен у відповіді |
| Using 'Respond to Webhook' Node | те, що задає Respond to Webhook | **стандарт для довгих задач:** 202 `{"job_id": …}` одразу, результат — колбеком |
| Streaming | потік | не використовуємо |

**Правило 100 секунд.** Усе, що може наблизитися до 100 с, — лише 202 + колбек. На n8n Cloud запит, на який
вебхук не відповів за 100 с, закінчується **524**; воркфлоу працює далі, але Next.js про результат не
дізнається. Не певні, скільки триває воркфлоу, — він асинхронний. Воркфлоу «40–90 секунд» — асинхронний без
варіантів.

Respond to Webhook спрацьовує один раз. Якщо воркфлоу завершився, не дійшовши до нього, — 200 зі стандартним
повідомленням; помилка до нього — 500. Тому в Next.js дивимось на код: очікуємо 202 (асинхронно) або 200
(Immediately).

## Тестовий і production URL

| | Тестовий | Production |
|---|---|---|
| Шлях | `/webhook-test/<path>` | `/webhook/<path>` |
| Працює | 120 с після «Listen for test event» | поки воркфлоу опублікований |
| Дані видно в редакторі | так | ні |

- У коді й `.env.example` — лише `/webhook`. Тестовий URL — тимчасово й лише у власному `.env.local`.
- Тестовий URL у `.env` — найчастіша причина «заявки мовчки губляться»: через 120 с він відповідає 404.
- n8n 2.x: публікація фіксує версію воркфлоу; production-виклики йдуть у неї. Після змін — Publish знову.
- На self-hosted шляхи змінюються змінними `N8N_ENDPOINT_WEBHOOK` / `N8N_ENDPOINT_WEBHOOK_TEST` — тоді це
  записують у `docs/n8n-integrations.md` проєкту.

## Коди відповіді n8n, які треба розрізняти

| Код | Що означає | Що робимо |
|---|---|---|
| 200 | Immediately прийняв | статус `sent` |
| 202 | Respond to Webhook прийняв, `job_id` у тілі | статус `queued`/`processing`, чекаємо колбек |
| 403 | Header Auth: неправильний або відсутній `x-n8n-token` («Authorization data is wrong!») | не повторюємо, статус `failed`, журнал без токена |
| 404 | воркфлоу не опубліковано або тестовий URL | не повторюємо |
| 5xx, 524, мережа, таймаут | збій | повтор (до 3 спроб разом, 1 с → 3 с) |
