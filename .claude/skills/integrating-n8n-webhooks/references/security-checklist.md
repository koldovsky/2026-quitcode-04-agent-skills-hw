# Безпека — одним списком

- [ ] **Секрети** лише в серверних змінних: жодного `NEXT_PUBLIC_N8N_*`, секрету в query string, у
      Client Component чи в журналі. У git — тільки `.env.example`: секрети — `change-me-…`, адреси —
      локальні, жодного `/webhook-test/`. (C1, C2, C9)
- [ ] **Модуль клієнта** `lib/n8n/client.ts` починається з `import "server-only"` — імпорт у Client
      Component стає помилкою збірки. Прямих `fetch` до n8n поза `lib/n8n/` немає. (C3)
- [ ] **Вихідна автентифікація**: Header Auth `x-n8n-token` (не query string), довгий випадковий
      токен, лише HTTPS. (C10)
      n8n порівнює токен звичайним `!==`, тож довжина й випадковість токена важливі. Де можна — IP
      allowlist на Webhook.
- [ ] **Вхідна автентифікація**: HMAC-SHA256 над `` `${timestamp}.${rawBody}` ``, перевірка довжини +
      `crypto.timingSafeEqual`, вікно часу ±300 с. Ні `===`, ні `!==` на підписах. (C4, C5)
- [ ] **Без секрету — нічого**: якщо `N8N_CALLBACK_SECRET` не задано, колбек-роут відповідає 500 на все.
      HMAC з порожнім ключем підробить будь-хто.
- [ ] **Сирі байти першими**: `request.text()`/`arrayBuffer()` один раз; `JSON.parse` — лише після
      перевірки підпису; ніякого `request.json()`. (C4)
- [ ] **Ключ колбека — з підписаного тіла**: заголовок `idempotency-key` не входить у HMAC, тому
      роут приймає лише `` `${data.jobId}:${event}` `` з тіла; інакше перехоплений колбек можна
      відтворити з новим ключем у межах вікна 300 с.
- [ ] **Запит — лише для своєї задачі, результат — фінальний**: колбек з `data.jobId`, що не
      дорівнює `job_id` з 202, → 409; готовий запис (`ready`) не перезаписуємо — інакше колбек
      іншого запуску підмінить документ, який клієнт уже бачив.
- [ ] **Ідемпотентність з обох боків**: Remove Duplicates у n8n за `idempotency-key`; у Next.js —
      унікальний «claim» ключа колбека в БД/KV (пам'ять процесу — лише для демо: на serverless обробники
      не ділять стан). Наші повтори й Retry On Fail у n8n роблять дублікати неминучими. (C10)
- [ ] **Таймаути**: `AbortSignal.timeout(10_000)` на кожну спробу виклику n8n; колбек підтверджуємо
      швидко — до 2xx лише мінімальний durable-запис, решта в `after()`. (C6)
- [ ] **Журнали**: подія, напрям, статус, тривалість, номер спроби, `x-correlation-id`, довжина тіла і
      sha256. Ніколи: тіла, ім'я, email, телефон, IP, токен, підпис, секрет, URL із query string. (C7)
- [ ] **Відповіді з помилкою** без внутрішніх подробиць (стек, SQL, URL n8n): 401 — з порожнім тілом.
- [ ] **Дані з колбека — недовірені навіть після підпису**: перевір форму; посилання показуй у UI лише
      якщо це `https:` URL (не `javascript:`); розміри рядків обмеж.
- [ ] **Правильний URL**: лише `/webhook/…`; `/webhook-test/…` живе 120 с. Після змін у n8n 2.x —
      Publish. (C1)
- [ ] **Ліміти розміру**: Server Action — 1 МБ за замовчуванням, вебхук n8n — 16 МБ, колбек — 64 КБ.
      Файли — посиланнями.
- [ ] **Server Action — публічний ендпоінт**: автентифікація, права й валідація всередині кожної дії
      (правило `server-auth-actions` скіла Vercel), повертаємо лише `{ status, id }`, не рядки з БД.
- [ ] **Runtime** — лише `nodejs` (за замовчуванням); `edge` застарілий і без `node:crypto`. (C8)
- [ ] **Публічна сторінка статусу** доступна за непередбачуваним id (UUID), не за порядковим номером;
      без персональних даних, які не вводив сам користувач.
