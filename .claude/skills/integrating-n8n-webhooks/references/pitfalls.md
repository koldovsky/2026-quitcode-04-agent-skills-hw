# Відомі пастки й межі скіла

## Пастки в документації й чужих скілах

- «Workflow got started» (документація) проти `{"message":"Workflow was started"}` (код n8n) — тому
  текст відповіді не парсимо, лише код статусу.
- Офіційний пакет скілів n8n пише, що Header Auth відхиляє з **401**. Код n8n повертає **403**
  («Authorization data is wrong!»); 401 — для Basic Auth і JWT.
- Той самий пакет пише, що секрет вузла Crypto не прив'язується до credential. Для Crypto v2 це вже не
  так: використовується Hmac Secret із Crypto credential.
- Приклад вебхука в документації Next.js передає токен у `?token=` у GET і порівнює через `!==`. GET
  кешується й потрапляє в журнали. У нас: токен у заголовку, підпис, `timingSafeEqual`.
- `req.json()` у колбек-роуті «працює» в демо, але ламає підпис, щойно n8n відформатує JSON інакше.
- `export const runtime = "edge"` зі старих прикладів — у Next 16 застарілий і без `node:crypto`.
- Тестовий URL «працює» лише 120 с після Listen — потім 404, а код, який не дивиться на статус, мовчки
  губить заявки. Завжди перевіряйте код відповіді й пишіть його в журнал.
- `JSON.stringify(lead)` у тілі — у n8n іде IP, user agent, нотатки. Лише мінімальний `data`.
