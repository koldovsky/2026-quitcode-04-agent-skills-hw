# Експлуатація: журнали, ліміти, локальний мок, пастки

## Журнали

| Пишемо | Не пишемо ніколи |
|---|---|
| подію, напрям (`n8n out` / `n8n in`), `x-correlation-id` | тіло запиту чи відповіді, `formData`, конверт |
| код статусу, тривалість, номер спроби | ім'я, email, телефон, IP, опис задачі клієнта |
| довжину тіла і його sha256 (якщо треба звірити з журналом n8n) | токен, підпис, секрет, повний URL з query string |

Відповіді з помилкою — без внутрішніх подробиць (стек, SQL, URL n8n, «який саме заголовок не зійшовся»).

## Ліміти

| Ліміт | Значення | Звідки |
|---|---|---|
| Тіло запиту до вебхука n8n | 16 МБ (`N8N_PAYLOAD_SIZE_MAX` на self-hosted) | n8n |
| Тіло Server Action | 1 МБ за замовчуванням (`serverActions.bodySizeLimit`) | Next.js |
| Відповідь вебхука на n8n Cloud | 100 с, далі 524 | n8n |
| Тестовий URL | 120 с після «Listen for test event» | n8n |
| Колбек у Next.js | 64 КБ тіла, вікно часу 300 с | наше рішення |
| Таймаут однієї спроби Next.js → n8n | 10 с, максимум 2 повтори (1 с, 3 с) | наше рішення |

Файли не передаємо — лише посилання на них.

## Локальна розробка: мок n8n

`scripts/mock-n8n.mjs` у цьому скілі — офлайн-«n8n» без залежностей: Webhook, Respond to Webhook, Header
Auth і підписаний колбек, як описано в контракті. Запускати з кореня проєкту:

```bash
node .claude/skills/integrating-n8n-webhooks/scripts/mock-n8n.mjs --help
# довгий воркфлоу: 202 одразу, підписаний колбек на callbackUrl із запиту через 5 с
node --env-file=.env.local .claude/skills/integrating-n8n-webhooks/scripts/mock-n8n.mjs --mode respond-202 --delay 5000
# як поводиться синхронне очікування на Cloud (524)
node .claude/skills/integrating-n8n-webhooks/scripts/mock-n8n.mjs --mode slow --cloud-timeout 5000
```

- З `N8N_WEBHOOK_TOKEN` у середовищі мок вимагає `x-n8n-token` (інакше 403); з `N8N_CALLBACK_SECRET` —
  надсилає підписані колбеки. Секрети — лише через `--env-file`, не прапорцями.
- `/webhook-test/<path>` мок приймає лише з `--listen` і лише 120 с — як n8n.
- Журнал мока: метод, шлях, статус, тривалість, **імена** заголовків, розмір і sha256 тіла, `auth=`,
  `idempotency=new|repeat|absent`, результат колбека. Значень і тіл він не пише.
- Очікуваний сценарій: `POST /webhook/quote-request -> 202 … auth=ok idempotency=new`, потім
  `callback POST …/api/n8n/quote-request -> 202`.
- `scripts/send-signed-callback.mjs` — матриця колбеків проти вашого роуту (правильний підпис, повтор,
  неправильний підпис, прострочений час…) з очікуваним кодом на кожен випадок.

## Відомі пастки

- Текст відповіді режиму Immediately: документація — «Workflow got started», код n8n —
  `{"message":"Workflow was started"}`. Тому дивимось лише на код статусу.
- Чужі скіли й статті пишуть, що Header Auth відхиляє з 401; n8n повертає **403**.
- Старі матеріали пишуть, що секрет вузла Crypto не береться з credential; для Crypto v2 — береться.
- У документації Next.js є приклад вебхука з токеном у query string (`?token=`, GET) і порівнянням через
  `!==` — не беремо його за зразок: GET-запити кешуються й осідають у журналах. У нас токен лише в
  заголовку, метод POST, колбек підписаний, порівняння — `timingSafeEqual`.

## Реєстр інтеграцій проєкту

Кожна інтеграція — рядок у `docs/n8n-integrations.md` проєкту (створіть, якщо немає):

| event | напрям | шлях n8n | режим | власник |
|---|---|---|---|---|
| `quote-request` | Next.js → n8n → колбек | `/webhook/quote-request` | Respond to Webhook 202 + колбек | ім'я відповідального |

## Поза межами скіла

- Побудова чи зміна воркфлоу в редакторі n8n, експорт / імпорт JSON воркфлоу, код для вузла Code.
