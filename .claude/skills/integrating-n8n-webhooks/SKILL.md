# Next.js ↔ n8n: контракт команди

Форма запускає воркфлоу n8n, n8n повідомляє про результат колбеком. Контракт узгоджений командою;
відхилятися — лише свідомо й письмово (у PR), а не «бо так згенерувалось». Деталі й «чому» — у
`references/`; тут — що зробити.

## Як робимо

**Змінні — лише серверні** ([references/contract.md](references/contract.md)): `N8N_WEBHOOK_BASE_URL`
(закінчується на `/webhook`), `N8N_WEBHOOK_TOKEN`, `N8N_CALLBACK_SECRET`, `APP_BASE_URL`. Жодного
`NEXT_PUBLIC_N8N_*`, жодних інших `N8N_*`. У `.env.example` — `change-me-…` і `/webhook`, ніколи
`/webhook-test/`. Змінили `.env.example` — скажіть людині оновити свій `.env.local` і перезапустити сервер.

**Виклик n8n** — лише з `lib/n8n/client.ts` (перший рядок `import "server-only";`, пакет не ставити).
Готовий шаблон — [references/code-templates.md](references/code-templates.md). Кожен виклик:

1. `POST ${N8N_WEBHOOK_BASE_URL}/<event>`, `<event>` — kebab-case, один шлях на подію.
2. Заголовки `content-type: application/json`, `x-n8n-token`, `idempotency-key` (UUID, створений **один
   раз** і збережений із записом), `x-correlation-id`.
3. Тіло — конверт `{ version: 1, event, data, callbackUrl? }`; `data` — мінімум полів, зібраний явно
   (ніколи весь рядок з бази: IP, user agent, нотатки, `rawPayload`).
4. `signal: AbortSignal.timeout(10_000)`; до 2 повторів (1 с, 3 с) лише на мережу / таймаут / 5xx / 524,
   з тим самим ключем. 4xx не повторюємо (403 — токен, 404 — не опубліковано / тестовий URL).
5. Дивимось лише на код статусу; текст відповіді не парсимо.

**З Server Action** — перевірки всередині дії (`server-auth-actions`), запис зі статусом `queued`,
відповідь `{ status, id }`, а виклик n8n — в `after()` (`server-after-nonblocking`). Результат виклику
(`sent` / `failed`, `jobId` з `202`) — у стан запису.

**Режим відповіді** ([references/response-modes.md](references/response-modes.md)): подія «до відома» —
Immediately; усе, що може тривати довше кількох секунд (генерація документа, кошторис) —
Respond to Webhook `202 {job_id}` + колбек. Не певні — асинхронно. Синхронно не чекаємо: n8n Cloud
обриває на 100 с кодом 524.

**Колбек** ([references/callback.md](references/callback.md)) — `app/api/n8n/[event]/route.ts`, строго
в порядку: 404 невідома подія / 415 не JSON → `raw = await request.text()` → 413 > 64 КБ → 401 якщо
`x-n8n-timestamp` поза ±300 с → HMAC `sha256` від `` `${ts}.${raw}` ``, довжини + `timingSafeEqual`
(401) → застовпити `idempotency-key` (повтор → 200 `{"duplicate":true}`) → лише тепер `JSON.parse`,
форма, ключ = `` `${data.jobId}:${event}` `` (400 + звільнити ключ) → зберегти стан **до** відповіді
(помилка → звільнити ключ) → 202 `{"ok":true}` → повільне в `after()`.

**Журнали** ([references/logging-and-limits.md](references/logging-and-limits.md)): подія, напрям,
correlation id, статус, тривалість, спроба, розмір / sha256 тіла. Ніколи — тіло, ім'я, email, телефон,
IP, токен, підпис, секрет, об'єкт запису чи помилки цілком. Відповіді з помилкою — без подробиць.

Налаштування n8n передаємо людині **текстом** ([references/n8n-setup.md](references/n8n-setup.md)) і
додаємо рядок у `docs/n8n-integrations.md` (event | напрям | шлях | режим | власник).

```

- [ ] 2. Лише N8N_WEBHOOK_BASE_URL / N8N_WEBHOOK_TOKEN / N8N_CALLBACK_SECRET (+ APP_BASE_URL); без NEXT_PUBLIC_.
- [ ] 3. /webhook/, не /webhook-test/ — у коді й .env.example.
- [ ] 4. Заголовки x-n8n-token, idempotency-key (збережений із записом), x-correlation-id; конверт {version, event, data}.
- [ ] 5. AbortSignal.timeout(10_000); ≤ 2 повтори лише на мережу/таймаут/5xx/524, той самий ключ.
- [ ] 6. Server Action відповідає { status, id } одразу; n8n — в after(); довгий воркфлоу — 202 + колбек.
- [ ] 7. Колбек: text() → розмір → час ±300 с → timingSafeEqual → ключ → JSON.parse → стан до 202.
- [ ] 8. Журнали й відповіді без тіл, персональних даних і секретів.
- [ ] 9. check-contract.mjs — 0 FAIL на змінах.
```

## Правила зупинки — зупинись і спитай людину, якщо:

- потрібно поставити тестовий URL (`/webhook-test/`) будь-куди, крім власного `.env.local` людини;
- секрет або токен мав би потрапити в клієнтський код, `NEXT_PUBLIC_*`, query string, журнал чи git;
- задача вимагає, щоб користувач синхронно чекав воркфлоу, який може тривати понад кілька секунд,
  або невідомо, скільки він триває, а людина просить «показати результат одразу»;
- у n8n треба передати персональні дані понад мінімум (IP, документи, повний рядок з бази);
- невідомі шлях вебхука, режим відповіді або формат колбеку конкретного воркфлоу клієнта;
- потрібно змінити воркфлоу в n8n, імпортувати / експортувати його JSON чи писати код для вузла Code;
- `check-contract.mjs` дає FAIL, який ви хочете «обійти», а не виправити, або перевірка заважає задачі;
- потрібна нова залежність (`npm install`) — `server-only` ставити не треба.
