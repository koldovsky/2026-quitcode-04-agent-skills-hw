# integrating-n8n-webhooks

Перші кодові проєкти команди — Next.js-форми поверх воркфлоу, які вже працюють в n8n:
форма запускає воркфлоу, n8n повідомляє колбеком, коли результат готовий. Без цього
контракту кожен проєкт наново винаходить ті самі рішення й наступає на ті самі граблі:
тестовий URL у продакшн-конфігу, форма, що синхронно чекає воркфлоу й обривається на
524, незахищений колбек-ендпоінт, подвійна обробка одного й того ж колбеку, персональні
дані в журналах. Повний текст рішень і чому саме так — у `references/`.

## Коли застосовувати

- Дія в Next.js має запустити воркфлоу n8n (вебхук) або прийняти від нього колбек.
- **Не** застосовувати: побудова/зміна воркфлоу в редакторі n8n (JSON не експортуємо й не
  імпортуємо — `references/n8n-setup.md` описує налаштування словами); код для вузла Code
  в n8n; черги й фонові воркери — на наші об'єми вистачає `after()` і колбеків.

## Контракт — стисло

**Змінні середовища** (лише server-only, ніколи `NEXT_PUBLIC_*`): `N8N_WEBHOOK_BASE_URL`,
`N8N_WEBHOOK_TOKEN`, `N8N_CALLBACK_SECRET`, `APP_BASE_URL`. Реальні значення — лише
`.env.local`; у `.env.example` — заглушки й лише production-шлях (`/webhook`, ніколи
`/webhook-test/`). Повний список і приклади — `references/env-and-request.md`.

**Виклик n8n** — один модуль `lib/n8n/client.ts` з `import "server-only";` першим рядком;
жодних прямих `fetch` до n8n деінде. `POST ${N8N_WEBHOOK_BASE_URL}/<event>` з заголовками
`content-type`, `x-n8n-token`, `idempotency-key` (той самий на всі спроби), `x-correlation-id`;
тіло — конверт `{version, event, data, callbackUrl?}` з мінімумом даних; `AbortSignal.timeout(10_000)`;
максимум 2 повтори (1 с, 3 с) лише на мережеву помилку/timeout/5xx/524, ніколи на 4xx.
Деталі — `references/env-and-request.md`.

**Хто викликає** — Server Action (з UI) чи Route Handler (не-React клієнт); ніколи
`export const runtime = "edge"`. Дія перевіряє сесію/права **всередині себе** (правило
`server-auth-actions` зі скіла `vercel-react-best-practices` — не повторюємо тут),
зберігає стан (напр. `queued`), одразу повертає `{status, id}`, а сам виклик n8n — у
`after()` (правило `server-after-nonblocking`). Деталі — `references/env-and-request.md`.

**Режим відповіді** — усе, що може наблизитись до 100 с, лише асинхронно: Respond to
Webhook → 202 `{job_id}` одразу, результат — колбеком. Таблиця режимів і 100-секундне
правило (524 на n8n Cloud) — `references/response-modes.md`, там само — тестовий vs
production URL.

**Колбек** — `POST /api/n8n/<event>` (`app/api/n8n/[event]/route.ts`), довіряємо лише
підпису. Порядок обробки — **саме такий**:

1. Невідома подія → 404; не `application/json` → 415 (до читання тіла).
2. `await req.text()` — сирий текст; ніколи `.json()`/`JSON.parse` до підпису.
3. Тіло > 64 КБ → 413.
4. `|now − x-n8n-timestamp| > 300с` → 401.
5. HMAC від `` `${timestamp}.${raw}` ``, звірити через `crypto.timingSafeEqual` (не `===`);
   не збігається → 401.
6. `idempotency-key` вже опрацьований → 200 `{"duplicate": true}`.
7. Тепер `JSON.parse`, перевірка форми й що `idempotency-key` дорівнює `` `${data.jobId}:${event}` ``
   з тіла → інакше 400.
8. Зберегти мінімальний стан **до** відповіді; якщо впало після кроку 6 — звільнити ключ.
9. 202 `{"ok": true}`.
10. Повільне (листи, сповіщення) — в `after()`.

Повний опис і «чому саме так» — `references/callback.md`. Налаштування на боці n8n
(словами) — `references/n8n-setup.md`. Журнали, ліміти й відомі пастки документації —
`references/pitfalls-and-logging.md`.

## Чекліст

```
- [ ] 1. Усі N8N_* змінні — server-only, жодна не з префіксом NEXT_PUBLIC_.
- [ ] 2. У .env.example — лише /webhook, production-шлях; тестовий URL — тільки в .env.local.
- [ ] 3. Виклик n8n — лише з lib/n8n/*, з `import "server-only";` першим рядком.
- [ ] 4. fetch до n8n має AbortSignal.timeout(10_000) і повтори лише на мережеву/5xx/524, не на 4xx.
- [ ] 5. Дія перевіряє сесію/права всередині себе; повертає лише { status, ... }.
- [ ] 6. Виклик n8n — у after(), не блокує відповідь користувачу.
- [ ] 7. Callback route: raw text → перевірка розміру/часу → timingSafeEqual → JSON.parse → idempotency за тілом → запис стану → 202.
- [ ] 8. Ніякого секрету/підпису/тіла запиту в журналах — лише подія, код, тривалість, sha256 довжини.
- [ ] 9. node scripts/check-contract.mjs — 0 FAIL.
```

## Правила зупинки — зупинись і спитай людину, якщо:

- Потрібен тестовий URL (`/webhook-test/`) деінде, крім тимчасово в `.env.local`.
- Секрет (`N8N_WEBHOOK_TOKEN`, `N8N_CALLBACK_SECRET`) опиняється там, де міг би потрапити
  в клієнтський код, query string чи журнал.
- Задача просить синхронно чекати відповідь воркфлоу довше кількох секунд — асинхронний
  режим (202 + колбек) не «опція на розсуд», а правило вище 100 с; якщо не певні, скільки
  триває воркфлоу, — питайте, а не вгадуйте.
- Незрозуміло, який шлях/подія — production, а який — випадковий/тестовий: не вгадувати
  production event-шлях.
- Задача вимагає змінити порядок обробки колбеку (`references/callback.md`) — це не
  «оптимізація», кожен крок там існує з причини.
