# Інтеграція з n8n через вебхуки

Next.js-форма запускає воркфлоу в n8n; n8n повідомляє про результат колбеком. Без спільного
контракту кожен проєкт наступає на ті самі граблі: тестовий URL губить заявки після закриття
редактора n8n, форма синхронно чекає довгий воркфлоу й на n8n Cloud це обривається кодом 524,
колбек нічим не захищений, а повтори n8n створюють дублікати. Цей скіл фіксує домовлений спосіб
уникнути всього переліченого; свідомий відступ від нього оформлюється в PR з поясненням, а не мовчки.

## Коли застосовувати

- Новий чи змінюваний виклик n8n-воркфлоу з Server Action чи Route Handler.
- Новий чи змінюваний колбек-роут, що приймає підписаний результат від n8n.
- **Не** застосовувати: побудова/зміна самого воркфлоу в редакторі n8n (клієнт робить це сам —
  дивись `references/n8n-setup.md`, це опис словами, не інструкція агенту щось міняти в n8n), чи
  інтеграції, що не йдуть через n8n.

## Як робимо

Повний контракт — у `references/`, тут лише те, що агент має зробити.

1. **Змінні середовища** — усі лише серверні (`N8N_WEBHOOK_BASE_URL`, `N8N_WEBHOOK_TOKEN`,
   `N8N_CALLBACK_SECRET`, `APP_BASE_URL`), ніколи з префіксом `NEXT_PUBLIC_`. Деталі, заголовки
   запиту, конверт тіла, таймаут і повтори, хто викликає (Server Action + `after()`, чи Route
   Handler; ніколи `runtime = 'edge'`) — `references/contract.md`.
2. **Режим відповіді** — усе, що може наблизитись до 100 секунд, лише асинхронно (202 + колбек);
   у коді й `.env.example` — лише `/webhook`, ніколи `/webhook-test/`. Таблиця режимів і різниця
   тестового/production URL — `references/response-modes.md`.
3. **Колбек-роут** (`app/api/n8n/[event]/route.ts`) — точний порядок обробки, 10 кроків: сирий
   текст тіла й перевірка підпису (`crypto.timingSafeEqual`, **не** `===`) до будь-якого
   `JSON.parse`; ідемпотентність застовплена й стан збережено до відповіді. Повний порядок,
   ідемпотентність з обох боків і таблиця журналів — `references/callback-processing.md`.
4. **Правила Vercel** `server-auth-actions` і `server-after-nonblocking` (зі скіла
   `vercel-react-best-practices`) — застосовуй за id, не переписуй їх тут.
5. Налаштування самого воркфлоу в n8n (для людини, не для агента) — `references/n8n-setup.md`.
6. Розбіжності документації й типові пастки — `references/known-pitfalls.md`.

## Чекліст

```
- [ ] 1. Усі N8N_* змінні — серверні, без NEXT_PUBLIC_.
- [ ] 2. Виклик n8n живе в одному серверному модулі (напр. lib/n8n/client.ts, import 'server-only').
- [ ] 3. Кожен fetch до n8n має AbortSignal.timeout; повтори — лише для мережевих помилок/5xx/524.
- [ ] 4. Довгі воркфлоу — 202 + колбек, ніколи синхронне очікування.
- [ ] 5. У коді й .env.example — лише /webhook, ніде /webhook-test/.
- [ ] 6. Колбек-роут рахує й звіряє підпис на сирому тілі до JSON.parse; timingSafeEqual, не ===.
- [ ] 7. Ідемпотентність застовплена до відповіді; при помилці кроку 7-8 звільнена назад.
- [ ] 8. У журналах немає тіл, PII, токена, підпису чи повного URL із query string.
```

## Правила зупинки — зупинись і спитай людину, якщо:

- Десь з'являється тестовий URL (`/webhook-test/…`) поза власним `.env.local` — не «тимчасово
  залиш», а зупинись і спитай.
- Секрет (`N8N_WEBHOOK_TOKEN`, `N8N_CALLBACK_SECRET`) мав би потрапити в Client Component, лог чи
  query string — не існує сценарію, де це прийнятно.
- Воркфлоу, тривалість якого невідома чи може наблизитись до 100с, доведеться чекати синхронно,
  бо асинхронний варіант (202+колбек) ще не готовий на боці n8n — зупинись, а не «поки що чекаємо
  синхронно, якщо задача цього потребує».

## Файли скіла

- `references/contract.md` — змінні середовища, заголовки й тіло запиту до n8n, таймаут/повтори,
  хто викликає (Server Action/Route Handler).
- `references/response-modes.md` — режими відповіді n8n, правило «100с → асинхронно», тестовий vs
  production URL.
- `references/callback-processing.md` — точний 10-крокий порядок обробки колбеку, ідемпотентність
  з обох боків, таблиця журналів.
- `references/n8n-setup.md` — налаштування воркфлоу в редакторі n8n словами (для людини, без
  експорту/імпорту JSON).
- `references/known-pitfalls.md` — розбіжності документації й типові пастки; ліміти.
- `scripts/check-contract.mjs` — статична перевірка коду проєкту на відповідність контракту;
  ≥5 перевірок з id, PASS/FAIL, файл:рядок для FAIL, код виходу ≠0 при FAIL. Запуск:
  `node scripts/check-contract.mjs [--root <тека>] [--help]`.
- `scripts/mock-n8n.mjs` — копія `tools/mock-n8n.mjs`, щоб скіл був самодостатнім і працював у
  будь-якому проєкті: `node scripts/mock-n8n.mjs --help`.
