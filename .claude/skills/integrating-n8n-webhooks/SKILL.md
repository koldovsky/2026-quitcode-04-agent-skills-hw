# Integrating n8n Webhooks

Next.js-форми й портали в проєктах команди працюють поверх n8n-автоматизацій: форма
запускає воркфлоу, n8n повідомляє результат колбеком. Контракт цієї інтеграції —
узгоджене рішення команди (`references/`), а не варіант на вибір: тестовий URL у коді,
незахищений колбек чи неправильний режим відповіді реально ламали продакшн раніше.

## Коли застосовувати

- Форма чи дія викликає n8n-воркфлоу (наприклад, «запит на кошторис», заявка, генерація
  документа).
- Потрібен ендпоінт, що приймає колбек від n8n після завершення воркфлоу.
- Переробка існуючого виклику n8n, який не відповідає контракту (тестовий URL у коді,
  синхронне очікування довгого воркфлоу, незахищений колбек).
- **Не** застосовувати: побудова/зміна самого воркфлоу в редакторі n8n, експорт/імпорт
  JSON воркфлоу, код для вузла Code в n8n.

## Як робимо

1. **Виклик n8n — лише з `lib/n8n/client.ts`**, перший рядок `import 'server-only'`.
   Деталі запиту (заголовки, конверт, таймаут 10с, повтори 2× з паузами 1с/3с лише на
   мережеву помилку/таймаут/5xx/524) — `references/outgoing-contract.md`.
2. **Хто викликає:** Server Action для дії з UI (auth і права всередині — правило
   `server-auth-actions`), Route Handler для не-React клієнта. Користувач не чекає на
   n8n: зберегти запис зі статусом одразу, виклик n8n — у `after()` (правило
   `server-after-nonblocking`). Ніколи `runtime = 'edge'`.
3. **Режим відповіді n8n:** усе, що може наблизитись до 100с, — лише асинхронно
   (Respond to Webhook, 202 + колбек). Деталі режимів і тестовий/production URL —
   `references/response-modes.md`.
4. **Колбек — `app/api/n8n/[event]/route.ts`**, обробка **у точному порядку 10 кроків**
   (перевірка події й content-type → сирий текст тіла → ліміт 64КБ → вікно часу 300с →
   HMAC через `timingSafeEqual` → застовпити idempotency-key → парсити JSON → зберегти
   стан → 202 → повільне в `after()`) — `references/callback-handling.md`. Порядок
   критичний: перестановка кроків ламає безпеку чи ідемпотентність.
5. **Налаштування вузлів n8n** (Webhook, Remove Duplicates, Respond to Webhook, Crypto,
   HTTP Request) словами, без експорту JSON — `references/n8n-setup.md`, коли треба
   пояснити клієнту або собі, що має бути в редакторі n8n.
6. **Журнали й ліміти** — `references/logging-and-limits.md`: що можна писати в лог,
   а що ніколи (PII, токени, тіла запитів).
7. **Відомі розбіжності документація/код** (перш ніж довіряти зовнішньому скілу чи
   документації n8n дослівно) — `references/known-pitfalls.md`.

Правила Vercel, на які спираємось за id (не копіюємо): `server-auth-actions`,
`server-after-nonblocking`.

## Чекліст
 1. Виклик n8n лише з lib/n8n/client.ts з import 'server-only'.
 2. У коді й .env.example — лише /webhook, ніколи /webhook-test.
 3. N8N_* змінні без префіксу NEXT_PUBLIC_.
 4. fetch до n8n має AbortSignal.timeout(10_000) і idempotency-key.
 5. Довгий воркфлоу — лише асинхронно (202 + колбек), не Immediately/Last Node.
 6. Виклик n8n і повільні побічні ефекти — у after(), не блокують відповідь користувачу.
 7. Колбек-роут: сирий текст тіла до JSON.parse, HMAC через timingSafeEqual (не ===).
 8. Ідемпотентність: idempotency-key застовплюється до обробки й звіряється з тілом.
 9. Журнали не містять PII, токенів, підписів, тіл запитів.
 10. Секрети лише в .env.local; .env.example — значення change-me-…

## Правила зупинки — зупинись і спитай людину, якщо:

- Незрозуміло, чи воркфлоу конкретної події швидкий (секунди) чи довгий — вибір режиму
  відповіді (синхронний/асинхронний) впливає на всю архітектуру, не вгадуй.
- Немає контракту на нову подію (`event`, форма `data`) — не вигадуй поля запиту сам,
  запитай, що саме очікує воркфлоу.
- Потрібно тимчасово використати тестовий URL (`/webhook-test/...`) для налагодження —
  повідом і переконайся, що це не потрапить у `.env.example` чи основний код.
- Секрет (`N8N_WEBHOOK_TOKEN`, `N8N_CALLBACK_SECRET`) потрібно передати кудись поза
  серверним модулем (клієнтський код, журнал, query string) — це порушення контракту,
  зупинись і спитай, навіщо.
- Синхронне очікування довгого воркфлоу здається простішим рішенням «для MVP» — це саме
  та ситуація, що ламається на n8n Cloud (524) і блокує наступні дії користувача.
