# Тест спрацювання скіла `integrating-n8n-webhooks` (Task E2)

Чи завантажує агент скіл тоді, коли задача про зв'язку Next.js ↔ n8n, і чи **не** завантажує на
схожі, але чужі задачі (вузол Code, експорт воркфлоу, вебхук Stripe, черги, форма без n8n).
Скіл обрано, бо в його `description` є і тригери, і явне «Не для: …» — його межі можна перевірити.

## Метод

- **Кожен запит — окрема нова сесія** Claude Code 2.1.283 без інтерактиву, з кореня проєкту (усі
  скіли на місці: три проєктні, особисті `find-skills` і `postgres-migrations`, вбудовані й
  синхронізовані з claude.ai). Скрипт запуску й сирі журнали `*.jsonl` — поза репозиторієм
  (`D:\leaddesk-e2-kit\`), у git не йдуть.
- Команда на кожен запит (запит — у stdin, UTF-8):
  ```
  claude -p --output-format stream-json --verbose --model opus --effort high \
    --allowedTools "Skill,Read,Grep,Glob" \
    --disallowedTools "Edit,Write,NotebookEdit,Bash,PowerShell,WebFetch,WebSearch,Agent,Workflow,Artifact,…,Read(./.env.local),Read(./.env)" \
    --max-budget-usd 1 --no-session-persistence
  ```
  з `ENABLE_CLAUDEAI_MCP_SERVERS=false` (як у A/B: конекторів claude.ai немає). `--allowedTools`
  лише дозволяє наперед, забороняє `--disallowedTools`: у сесії лишаються тільки `Read`, `Grep`,
  `Glob`, `Skill`, `ToolSearch`, `CronList`, `ListAgents` (перевірено пробним запуском — подія
  `init` у журналі), тож агент нічого не змінює.
- **Ознака спрацювання:** у журналі виклик інструмента `Skill` з `integrating-n8n-webhooks` або
  читання файлу з `.claude/skills/integrating-n8n-webhooks/`. Інші викликані скіли теж записуємо.
- Модель і рівень міркування — `opus` (`claude-opus-5-5`), `high`, однакові для всіх запусків.

## Що змінено в `description` і чому

**Не змінювали.** Прогін 1 дав 12/12: жодного хибного спрацювання й жодного пропущеного, а на
межових запитах (N1 — вузол Code, N2 — експорт воркфлоу, N3 — вебхук не від n8n) агент повівся саме
так, як написано в `description`. Міняти формулювання без помилки, яку воно виправляє, — ризик
зламати те, що працює, і без даних сказати, чи стало краще, неможливо. Що в `description`,
судячи з результатів, «несе» спрацювання:

- **конкретні предмети контракту** замість загального «інтеграція з n8n» — «виклик вебхука n8n із
  серверного коду», «підписаний колбек n8n → Next.js», «змінні N8N_*», «таймаут і повтори», «режими
  відповіді (… 202 + колбек)». Слова «524» у `description` немає, а T5 спрацював на суть: форма
  кошторису, що чекає на воркфлоу, — це «форма… запускає воркфлоу n8n» і «запит на кошторис через n8n»;
- **фрази команди**: «відправ заявку в n8n», «колбек від n8n», «n8n має повернути результат» — T1,
  T2 і T6 сформульовано інакше, але по суті те саме, і скіл спрацював першою дією;
- **явне «Не для: …»** (побудова чи експорт воркфлоу в редакторі n8n, код вузла Code, черги й фонові
  воркери) — найсильніше це видно на N1 і N2: там є «n8n», але скіл не завантажено. N4 (черга) слова
  «n8n» не містить, тож він показує менше — лише що «фонова розсилка» сама по собі скіл не тягне.

Окремо видно, що скіл працює не лише як довідка: у T3 і T6 агент застосував **правила зупинки**
(не писав код, поки не з'ясовано режим воркфлоу, дані для n8n і права; не вибирав сам сховище
ключів для продакшну).

три прогони. Скіл завантажується першою дією на всі вісім формулювань задач Next.js ↔ n8n, зокрема

типи задач (наприклад, інша подія n8n з режимом Immediately).
