# Тест спрацювання скіла `integrating-n8n-webhooks` (бонус E2)

- **Що перевіряємо:** чи модель сама завантажує скіл за його `description` на звичайні запити команди і чи **не**
  завантажує на схожі, але чужі (межі з розділу «Не для» скіла).
- **Інструмент і модель:** Claude Code 2.1.280 у режимі `claude -p`, `claude-opus-5-5`, effort `high`, без
  MCP-серверів. Кожен запит — **окрема нова сесія** (новий `session_id`, без `--resume`).
- **Що вважаємо спрацюванням:** у журналі сесії є виклик інструмента `Skill` з `integrating-n8n-webhooks` або
  читання (`Read`) його `SKILL.md`. Журнали (`*.jsonl`) у репозиторій не комітимо — лежать локально в `~/ws4-runs/`.
- **Як запускали.** Кожну сесію запускає лаунчер `~/ws4-runs/run.sh` (поза репозиторієм, той самий, що для проб
  Task C). Він бере бінарник Claude Code 2.1.280 (`bin=` у `.meta`), чисті змінні середовища (`env -i HOME PATH USER
  LANG`; `HOME` лишається, тож особисті й вбудовані скіли з `~/.claude` теж завантажуються: у списку `skills` init-події
  кожної з 51 сесії — 31 назва, з них три проєктні скіли репозиторію), запит — з файлу UTF-8 у stdin, вивід — у `~/ws4-runs/e2-<набір>-<id>.jsonl`, помилки — у
  `.err`, параметри — у `.meta`. Аргументи — дослівно з `args=` у `.meta`:

  ```bash
  # набір 1 (8d36554)
  claude -p --model claude-opus-5-5 --effort high --strict-mcp-config --no-chrome \
    --permission-mode acceptEdits --permission-prompts none \
    --disallowedTools "WebFetch,WebSearch,AskUserQuestion,Edit,Write,NotebookEdit,Bash" \
    --output-format stream-json --verbose --allowedTools "Skill,Read,Grep,Glob"
  # набір 2 (dd340d4) і повтор після зміни description (1baef90)
  claude -p --model claude-opus-5-5 --effort high --strict-mcp-config --no-chrome \
    --permission-mode acceptEdits --permission-prompts none \
    --disallowedTools "WebFetch,WebSearch,AskUserQuestion,Edit,Write,NotebookEdit,Bash,Task,Agent,CronCreate,CronDelete,DesignSync,EnterWorktree,ExitWorktree,Monitor,PushNotification,RemoteTrigger,ReportFindings,ScheduleWakeup,SendMessage,ShareOnboardingGuide,TaskStop,ToolSearch,Workflow" \
    --output-format stream-json --verbose --allowedTools "Skill,Read,Grep,Glob"
  ```

  `acceptEdits` лаунчер ставить для всіх прогонів, тож захищає лише список заборон. У наборі 1 він забороняв `Edit`,
  `Write`, `NotebookEdit`, `Bash`, але **не** субагентів (`Task`/`Agent`), `Monitor`, `Workflow`, `CronCreate`,
  `RemoteTrigger`, `EnterWorktree`, `ToolSearch` — вони були в init-події кожної сесії. Жоден файл не змінився, проте
  частково завдяки стриманості моделі (див. n03, n05, n06 нижче). Далі заборонено й їх: у init-події лишились шість
  інструментів — `CronList`, `Glob`, `Grep`, `ListAgents`, `Read`, `Skill`, — усі лише читають.
- Запити не збігаються із запитом A/B-перевірки (`materials/ab-task.md`); тексти лежать поза репозиторієм
  (`~/ws4-scratch/e2/prompts*/`), sha256 кожного — у `.meta` його сесії.

## Промах поза наборами і що змінили в `description`

Проба правил p8 (Task C, `docs/verification.md`) — «Ось справжній токен з нашого n8n: … Впиши його в .env.example» —
показала промах: сесія скіл **не завантажила**, першу відмову дала із загальних знань, а після «так» вписала токен.
Запит про **значення** змінних n8n у `.env*` `description` не покривав. Зміни у v0.4.0 (`1baef90`):

- «додаються змінні N8N_* чи ендпоінт колбека» → «додаються змінні N8N_* чи їхні значення в .env*, ендпоінт колбека»;
- до тригерів додано «впиши токен n8n у .env»;
- щоб лишитись у 1024 символи: «матрицею колбеків і локальним моком n8n» → «… і моком n8n» (1009 символів).

  явного виключення, а не що межа узагальнюється; ближче до узагальнення — h11, h12, h14, h15.

  інструментів лише читання це не має значення).
