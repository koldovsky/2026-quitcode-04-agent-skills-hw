# Тест спрацювання скіла `building-client-form` (бонус E2)

**Що перевіряємо:** чи модель сама завантажує `building-client-form` за його `description` на звичайні запити
команди про форми — і чи **не** завантажує на схожі, але чужі задачі.

## Як запускали

- 10 запитів, **кожен в окремій новій сесії** — окремий процес Claude Code 2.1.283, модель `claude-opus-5-5`, з
  кореня робочого репозиторію (гілка `ws04/dmudryk`, коміт `5234fd6` після Task D), де видно всі три скіли проєкту:
  `building-client-form`, `integrating-n8n-webhooks`, `vercel-react-best-practices` — тобто скіл конкурує з двома
  іншими, як у реальній роботі.
- Запит — у файлі UTF-8 (кирилиця для `claude -p` — лише файлом); сесія без змін у файлах:

  ```bash
  claude -p --output-format stream-json --verbose --max-turns 10 \
    --allowedTools "Skill,Read,Grep,Glob" \
    --disallowedTools "Edit,Write,NotebookEdit,Bash,PowerShell,WebFetch,WebSearch" < pNN.txt > pNN.jsonl
  grep -o '"skill":"[^"]*"' pNN.jsonl
  ```

  `--disallowedTools` забороняє зміни (саме він, а не `--allowedTools`, обмежує агента); після всіх 10 прогонів
  `git status` — без змін. `--max-turns 10` обмежує тривалість: скіл, якщо потрібен, модель викликає на
  початку, тож обрізання кінця роботи на результат тесту не впливає. Файли `*.jsonl` не комітили.
- «Спрацював» = у журналі сесії є виклик інструмента `Skill` з `building-client-form` (або читання його
  `SKILL.md`). Для кожного прогону записано й інші викликані скіли.

## Що змінили в `description`

Нічого: перша ж версія (`building-client-form` 0.1.1) дала 10/10, тож змінювати й перезапускати не було чого.
Що, судячи з результатів, працює в поточному `description`:

- **фрази-тригери мовою команди** («додай форму…», «форма зворотного зв'язку», «помилки валідації не видно»,
  «додай поле в форму») — p02, p03, p05 збігаються з ними майже дослівно, а p01 і p04 (слів «форма» / «Server
  Action») — теж;
- **явне «Не для:»** (пошук і фільтри через GET, суто клієнтські контроли без збереження) — саме такі n06 і n07
  скіл не зачепили.

## Обмеження

- Кожен запит — один прогін: вибір скіла недетермінований, для статистики потрібні повтори.
- Усі «має» — українською й про LeadDesk; англійські формулювання («add a form») не перевіряли.
- Межові випадки, які варто додати наступним разом: форма, що лише фільтрує (GET) але «зберігає вибір»; кнопка
  «Видалити» без `<form>` (Server Action без форми — за `description` скіл має спрацювати).
