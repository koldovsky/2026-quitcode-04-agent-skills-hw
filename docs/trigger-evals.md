## Що змінили в `description` і чому

Промах №5: частина «Use when» описувала лише задачі, де код **змінюють** («код запускає воркфлоу…,
змінює такий виклик, змінні N8N_* чи .env.example»). Питання про **налаштування / деплой / діагностику**
зв'язки під це не підпадало, тож модель відповіла сама з коду.

Зміни (коміт `8f09320`, версія `0.1.2`):
- у «Use when» додано: «…а також коли питають, як налаштувати, задеплоїти чи перевірити зв'язку
  застосунку з n8n (змінні середовища, секрети, URL вебхука) або чому дані не доходять у n8n»;
- тригери: додано «які змінні потрібні для n8n», «n8n на продакшені»; прибрано «n8n повідомить, коли
  готово» (покривається «колбек від n8n»);
- щоб лишитись у межах 1024 символів, стиснуто перелік деталей контракту (1021 символ).

Межі «Не для» не змінювались — і в обох проходах скіл не спрацював на код для вузла Code і на
налаштування розкладу в редакторі n8n, тобто розширення «коли» не зробило його надто жадібним.
