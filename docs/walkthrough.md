# Домашнє завдання — Воркшоп 4

**Тема:** Agent Skills: упаковка експертизи команди
**Формат:** ставите чужий скіл (skill) як залежність — з рев'ю й закріпленою версією; пакуєте
експертизу команди у два власні скіли; перевіряєте A/B-прогоном, чи скіл змінює результат
**Час:** ~3 години
**Здача:** Pull Request у starter-repo (CodeRabbit зробить рев'ю)

WS3 дав агенту правила: короткі домовленості, які він бачить у кожній сесії. Але частина знань
команди — це не одне речення, а процедура з довідкою й перевірками: як закріпити чужу залежність,
як зробити форму, як говорити з n8n. Скіл — тека з `SKILL.md`, яку агент завантажує лише тоді, коли
задача цього потребує. Сьогодні — як узяти чужий скіл безпечно, як написати свій і як перевірити,
що він працює.

### Як перевірити, що агент бачить скіли

Знадобиться в кожному завданні. Перевіряйте в **новій** сесії: так ви бачите те, що побачить колега,
який щойно відкрив проєкт.

- **Claude Code:** `/context` → розділ Skills (назва й джерело кожного скіла) або `/skills`.
  Без інтерактивної сесії, з теки проєкту:
  ```bash
  MSYS_NO_PATHCONV=1 claude -p "/context"
  ```
- **Cursor:** новий чат, запит «які skills тобі доступні? не відкривай файлів».
- Будь-який інструмент: запит «які skills тобі доступні?» у новій сесії.

### Windows + Git Bash: що варто знати

- Команди в інструкції — для **Git Bash**. Команди `node …`, `npm …`, `git …` однакові й у
  PowerShell; відрізняється лише змінна перед командою: у bash `DISABLE_TELEMETRY=1 npx …`, у
  PowerShell `$env:DISABLE_TELEMETRY=1; npx …`.
- Git Bash перетворює аргумент `/context` на шлях Windows. Для команд `claude` зі слешем додавайте
  `MSYS_NO_PATHCONV=1` (як вище). Для `git` і `node` — не треба.
- Запит кирилицею для `claude -p` передавайте файлом (`claude -p < prompt.txt`, файл в UTF-8), а не
  аргументом.
- Порт зайнятий (`EADDRINUSE`): зупиніть свій попередній сервер (Ctrl+C). Якщо він «загубився»:
  `netstat -ano | grep :3000` → `taskkill //PID <pid> //F` (у Git Bash — саме `//`). Зупиняйте
  лише свої процеси. Перевірити, що на `:3000` саме LeadDesk, а не чужий застосунок:
  `curl -s localhost:3000 | grep -o "<title>[^<]*"`. Якщо звільнити порт не вдається, запустіть на
  іншому (`npm start -- -p 3001`) — але тоді той самий порт має бути **скрізь**: `U=…` у замірах,
  `APP_BASE_URL` у `.env.local` (із перезапуском `npm start`) і `--callback-url` мока. Інакше
  виміряєте чужий застосунок, а колбеки n8n підуть не на той сервер.
- `npx skills@1.7.0 add` за замовчуванням створює на Windows **junction**, який git комітить як
  другу повну копію. Тому в Task A — `--copy` (пояснення там).
- Версію CLI закріплено: `npx skills@1.7.0`. Поведінку, описану в Task A (junction, `--copy`,
  показ аудитів, `--yes` в агентській сесії), перевірено саме на 1.7.0; нова версія може поводитись
  інакше.

2. **Прочитати файли саме цієї версії**, а не `main`:

### 2. Встановлення з закріпленою версією

Запускайте **самі, у своєму терміналі** — не просіть агента (див. вище про `--yes`):

```bash
DISABLE_TELEMETRY=1 npx skills@1.7.0 add vercel-labs/agent-skills#agent-skills-063bee94c3f4df8453406c830b0a7df0f2860278 \
  --skill vercel-react-best-practices -a claude-code --copy
```

CLI перепитає (у звичайному терміналі, не в агентській сесії):

- `npx` при першому запуску — `Ok to proceed? (y)` → `y`;
- `Installation scope` → **Project**. `Global` кладе скіл у `~/.claude/skills/`: у git не потрапить
  нічого, а особиста копія потім «забруднить» прогін A в Task D;
- `Proceed with installation?` → `Yes`.

Щоб побачити аудити перед підтвердженням (крок 1.3), запустіть ту саму команду **без**
`DISABLE_TELEMETRY=1`: з цією змінною блоку «Security Risk Assessments» не буде.

- `#<тег>` — закріплена версія: CLI клонує саме її, а `npx skills@1.7.0 update` перевіряє скіл за цим тегом.
- `--copy` — справжні файли. Без нього CLI кладе файли в `.agents/skills/`, а в `.claude/skills/`
  ставить посилання: на Windows — junction з абсолютним шляхом `D:\…`, який git комітить як
  **другу повну копію** (150 файлів замість 75); на macOS/Linux — symlink, який у клоні на Windows
  стає текстовим файлом зі шляхом, і скіла не видно.
- `-a claude-code` без `cursor` — бо для Cursor CLI додає ще одну копію в `.agents/skills/`, а Cursor
  і так читає `.claude/skills/`.

Перевірте й закомітьте:

```bash
find .claude/skills/vercel-react-best-practices -type f | wc -l   # 75 (у клоні тега — 76: CLI не копіює metadata.json)
ls .agents 2>/dev/null || echo "no .agents - ok"
git status --short                                                  # тека скіла + skills-lock.json
git add .claude/skills/vercel-react-best-practices skills-lock.json
git commit -m "skills: vendor vercel-react-best-practices pinned to agent-skills-063bee9"
```

`skills-lock.json` фіксує джерело, тег і хеш. Відновлення з нього (`npx skills@1.7.0 experimental_install`)
пише лише в `.agents/skills/`, яку Claude Code не читає, — тому справжні файли тримаємо в git.

### 4. Базова лінія: числа до виправлень

Міряйте **продакшн-збірку**: у режимі `npm run dev` час з'їдає компіляція.

```bash
npm run build && npm start        # http://localhost:3000
```

В іншому терміналі (cookie — сесія демо-користувача Olena з демо-входу):

```bash
C="leaddesk_session=demo-u_olena"
U=http://localhost:3000/dashboard
curl -s -o /dev/null -b "$C" "$U"                                   # прогрів
for i in 1 2 3; do
  curl -s -o /dev/null -b "$C" -w "TTFB %{time_starttransfer}s, total %{time_total}s\n" "$U"
done
curl -s  -b "$C" "$U" | wc -c                                       # розмір HTML, байти
curl -sL -b "$C" -H "RSC: 1" "$U" | wc -c                           # розмір RSC-відповіді, байти
```

Що ще можна виміряти — залежно від правил, які застосуєте:

| Що змінює правило | Що міряти | Як |
|---|---|---|
| Порядок і паралельність запитів, стрімінг | час до першого байта й усієї сторінки | `curl` вище, 3 прогони |
| Кешування й дедуплікацію запитів | скільки разів виконався кожен `db:<запит>` за один запит сторінки | у терміналі `npm start`: на скільки зросли лічильники `db:…` після одного `curl` |
| Що передається в Client Component | розмір HTML і RSC-відповіді; які поля ліда доходять до браузера | `curl … \| wc -c`; `curl … \| grep -o '<поле>' \| head` |
| Що потрапляє в клієнтський JS | JS, який браузер вантажить при відкритті `/dashboard` | DevTools → Network → JS, Disable cache, сума внизу; або `npx next experimental-analyze` (враховує й чанки, що вантажаться пізніше) |
| Що відбувається після відповіді | час відправки форми | DevTools → Network → запит `POST /` після «Надіслати» |

Для форми: мок у режимі, коли вебхук відповідає після завершення воркфлоу (2 с). Щоб замір був
чесним, у **`.env.local`** (це налаштування, не код; `.env.example` не чіпаємо — він знадобиться
в Task C) поставте production-URL мока й перезапустіть `npm start` — змінні читаються на старті:

```bash
# .env.local
N8N_WEBHOOK_URL=http://127.0.0.1:5678/webhook/lead-created
```

```bash
node tools/mock-n8n.mjs --mode last-node
```

Замір рахується, лише якщо в журналі мока на вашу відправку є `POST /webhook/lead-created -> 200
in ~2000 ms`. Рядок `-> 404 in 2 ms` означає, що «воркфлоу» не запускався, а форма здається швидкою
через те, що код не дивиться на відповідь, — такий замір не записуйте. (Тестові URL `/webhook-test/…`
мок, як і n8n, приймає лише 120 секунд після запуску з `--listen`; для кількох замірів до і після
виправлень це незручно.)

## Task B — Власний скіл лише з інструкцій: `building-client-form` _(~25 хв)_

**Робоча ситуація.** Кожен проєкт агенції починається з форми: заявка, кошторис, зворотний
зв'язок, налаштування. Кожен розробник — і кожен агент — робить її по-своєму: дія без перевірки
прав, помилки, яких не чує скрінрідер, `console.log(formData)`, лист клієнту, на який користувач
чекає 3 секунди. Один патерн — у скіл, і він однаковий у всіх проєктах.

1. Скопіюйте `docs/templates/SKILL-template.md` у `.claude/skills/building-client-form/SKILL.md`.
   Лише інструкції: без `scripts/` і `references/`.
2. **Frontmatter:**
   - `name: building-client-form` — **рівно** як назва теки;

Скопіюйте `docs/templates/ab-validation.md` у `docs/ab-validation.md` і заповніть: для кожного
прогону — видимі скіли, виклик скіла, `check-contract.mjs` (id + PASS/FAIL), журнал мока, час
форми, журнал сервера, змінені файли й посилання на діф у `docs/ab/`; таблиця порівняння; висновок.

> **Мок доступний в обох прогонах**, і в його `--help` описано схему підпису колбека. Якщо агент без
> скіла прочитав мок і взяв контракт звідти — це чесний результат. Запишіть, **звідки саме** агент
> узяв домовленості.

> **Якщо різниці немає — це теж результат.** Поясніть її відсутність спостереженнями з журналу
> сесії: що агент читав, що запускав, звідки взяв рішення.

Копії після звіту можна видалити: `rm -rf ../leaddesk-ab-a ../leaddesk-ab-b ../leaddesk-main ../review-agent-skills`.

**Перевірка:** один запит без змін, дві нові сесії, у копії A немає скіла; `materials/`, `docs/`,
`README.md`, `.coderabbit.yaml` і `.github/` немає в обох; для кожного прогону — `check-contract.mjs`,
журнал мока, час форми, журнал сервера, змінені файли, діф у `docs/ab/`; висновок спирається на ці
дані.

## Task E (bonus) — одне з трьох _(~20 хв)_

**Робоча ситуація.** Скіли в команді множитимуться — чужі й свої. Хтось має вміти сказати «цей
ставимо, цей ні» і «цей спрацьовує, коли треба».

**E1 · Рев'ю чужого пакета n8n-скілів — без встановлення.** Оберіть
[czlonkowski/n8n-skills](https://github.com/czlonkowski/n8n-skills) або
[n8n-io/skills](https://github.com/n8n-io/skills). Шаблон `docs/templates/skill-review.md` →
`docs/skill-review-n8n.md`. Читайте на GitHub або з неглибокого клону поза репозиторієм; запишіть SHA
коміту, який переглядали (`git -C <тека> rev-parse HEAD`). **Не відкривайте клон як проєкт в агенті**
і нічого не встановлюйте: пакет може принести хуки, MCP-сервери й вимогу API-ключа. Окремо
перевірте твердження пакета про n8n проти записки команди (розділ «Відомі пастки»).

**E2 · Тест спрацювання власного скіла.** Для `building-client-form` або
`integrating-n8n-webhooks` — ≥ 10 запитів: ~5, на які скіл **має** спрацювати, і ~5 схожих, на які
**не має** (для n8n-скіла, наприклад, «напиши код для вузла Code в n8n»). Кожен — у новій сесії.
Швидше без інтерактиву, з теки проєкту (запит — у `prompt.txt`, UTF-8):

```bash
claude -p --output-format stream-json --verbose --allowedTools "Skill,Read,Grep,Glob" \
  --disallowedTools "Edit,Write,NotebookEdit,Bash" < prompt.txt > run.jsonl
grep -o '"skill":"[^"]*"' run.jsonl        # які скіли викликано
```

`--allowedTools` лише **заздалегідь дозволяє** інструменти, а не обмежує їх: у режимі `acceptEdits`
чи з дозволами з ваших налаштувань агент однаково міг би змінювати файли. Забороняє
`--disallowedTools` — з ним агент не змінить файлів, а виклик скіла видно. Таблиця «запит →
очікування → результат» і що ви змінили в `description` — у `docs/trigger-evals.md`. Файли `run.jsonl`
не комітьте.

**E3 · Ті самі скіли в Cursor.** Відкрийте репозиторій у Cursor. Новий чат — чи бачить він три скіли
з `.claude/skills/`; ті самі звичайні запити, що в Task B і C, — чи спрацювали скіли. Розділ «Cursor» у
`docs/verification.md`: версія, що побачили, чим поведінка відрізняється від Claude Code.
