Як проводити — `docs/walkthrough.md`, Task D: кожен прогін у власній копії поза репозиторієм
(`git archive` коміту BASE + скіли з HEAD, без `materials/`, власний `git init`). Для цієї гілки BASE —
`558014e` (останнє виправлення Task A; далі починається код n8n: `1230ddf`), скіли — з HEAD
`ws04/sample`. Шаблон звіту — `docs/templates/ab-validation.md`.

Що має з'явитися тут для кожного прогону:

1. BASE і коміт скілів, модель і рівень міркування; які скіли агент бачив — окремим запуском
   `claude -p "/context"` у теці копії, не в сесії прогону.
2. Чи викликав агент скіл (інструмент `Skill` або читання `.claude/skills/integrating-n8n-webhooks/**`).
3. Вивід `node .claude/skills/integrating-n8n-webhooks/scripts/check-contract.mjs --root ../leaddesk-ab-<a|b>`
   (id + PASS/FAIL) — до прогону (базова лінія) і після.
4. Журнал мока під час сценарію «надіслати форму → дочекатися колбеку → відкрити `/quotes/[id]`»:
   URL (`/webhook/` чи `/webhook-test/`), заголовки, `auth=`, `idempotency=`, колбек і відповідь застосунку.
5. Час від «Надіслати» до відповіді форми.
6. Що агент пише в журнал сервера (тіла, персональні дані?).
7. `git diff --cached --stat` у копії (після `git add -A`), фінальна відповідь агента, його запитання;
   звідки агент узяв домовленості.
8. Висновок: різниця між A і B — або чесне «різниці немає» з поясненням за журналом сесії.
